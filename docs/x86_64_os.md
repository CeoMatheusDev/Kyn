# Kyn for x86-64 operating systems

**Status:** architecture plan; none of the freestanding or kernel-specific items below are implemented merely by documenting them. The currently validated native backend still emits Linux user-space System V assembly. This document defines the next target without changing that compatibility contract.

## Goal

Make Kyn a practical implementation language for an x86-64 operating system: boot-time code, kernel core, interrupt and exception entry, physical/virtual memory managers, scheduler, drivers and user-space ABI components.

The first supported OS target is deliberately narrow:

- Architecture: x86-64 (AMD64).
- Object format: ELF64, little-endian, System V-compatible ELF conventions where applicable.
- Kernel execution model: freestanding, privileged code, no libc, no host process startup.
- Initial compiler output: relocatable ELF object(s), followed by a user-supplied linker script and external linker.
- Boot protocol: keep the compiler independent of firmware; initially consume a documented bootloader handoff contract. UEFI loader work is a separate component.
- Runtime: none required. Any startup, allocator, panic path and hardware abstraction must be explicit Kyn or assembly code.

This is not the same target as `x86_64-linux-gnu`. A Linux executable depends on the Linux process ABI and syscall numbers; a kernel image owns its entry point, memory map, interrupt state and platform ABI.

## Non-negotiable compiler properties

1. **No implicit host assumptions.** Target, object format, ABI, code model and runtime mode are explicit compiler inputs.
2. **No hidden runtime.** Freestanding output must not synthesize libc calls, `main`, constructors, TLS setup or process-exit code.
3. **Stable layout.** Kernel-facing aggregates need specified size, alignment, field offsets, enum representation and padding.
4. **Explicit effects.** MMIO and interrupt-visible memory operations need volatile/atomic semantics that survive optimization.
5. **Auditable unsafe boundary.** Port I/O, MMIO, physical addresses, inline assembly, interrupt entry and raw pointer construction must be explicit and locally reviewable.
6. **Reproducible artifacts.** The compiler must emit inspectable assembly/IR and ELF objects; tests must validate ELF headers, sections, relocations and disassembly, not just compiler exit status.

## Target model

Introduce a target description only when it is consumed by the driver and at least one backend. Keep the frontend and syntax target-independent.

Proposed target identity:

```text
arch       = x86_64
vendor     = unknown
os         = none
abi        = kyn-kernel (initially)
format     = elf
runtime    = freestanding
code_model = kernel
red_zone   = disabled
```

The exact spelling of CLI flags is open, but the semantic dimensions must remain separate. In particular, `--target` must not silently imply a calling convention or runtime.

Suggested compiler boundaries:

```text
src/
  target/
    target.zig          # parsed target + validated feature set
    data_layout.zig     # pointer width, integer layout, alignment
    abi.zig             # argument/return and stack rules
    x86_64/
      kernel.zig        # kernel ABI and machine constraints
      linux_sysv.zig    # existing user-space ABI contract
  object/
    elf.zig              # ELF64 relocatable writer/reader validation
  codegen/
    x86_64.zig           # instruction selection, no OS policy
```

Do not create empty placeholder modules. First extract a tested target contract from existing code, then migrate one consumer at a time. The current assembly backend may remain as a Linux-hosted bootstrap path while the freestanding object path is introduced.

## x86-64 kernel ABI contract

The initial kernel ABI must be documented and tested before code generation depends on it.

- Stack is 16-byte aligned at every compiler-generated call boundary; the exact entry-stack state is established by startup code.
- The 128-byte System V red zone is **not** available in kernel mode and must never be used.
- Kernel entry is a symbol selected by the linker/boot contract, not an implicitly generated `main`.
- Interrupt/exception entry is not an ordinary function call. Interrupt stubs save the architecturally required state and transition to a normal Kyn function only through a specified wrapper ABI.
- Callee-saved and caller-saved register sets are explicit. Interrupt wrappers preserve every register required by the interrupted context, independently of the ordinary function ABI.
- The initial code model is `kernel`; relocation and address materialization rules must be checked against the selected linker script and image placement.
- Do not emit floating-point/SIMD instructions before the kernel has explicitly enabled and configured the relevant processor state.
- The compiler must not assume a userspace TLS segment, stack protector runtime, unwind runtime or exception runtime exists.

The first implementation should use a conservative integer-only calling convention, with stack spill support before expanding aggregate passing. Reusing the current six-register aggregate convention as a kernel ABI without a written contract is prohibited.

## Language features required for kernel work

The feature order is dependency-driven, not syntax-driven.

### 1. Target and layout

- Explicit `usize`/pointer width from target data layout.
- `#[repr(C)]` (or an equivalent syntax selected by the language design) with deterministic padding.
- Explicit alignment and packed-layout support only with unaligned-access diagnostics or unsafe operations.
- Compile-time `size_of`, `align_of` and `offset_of` assertions.
- Extern declarations and a stable C-compatible ABI for boot protocol structures.

### 2. Memory and hardware effects

- `const` pointers and explicit mutability/aliasing rules.
- A real `unsafe { ... }` AST and semantic boundary.
- `volatile` loads/stores for MMIO; volatile is not a substitute for atomicity or memory barriers.
- Atomic operations and ordering semantics only after target lowering is specified.
- Explicit pointer provenance, nullability and lifetime rules; no implicit dereference checks in the kernel hot path.
- Port I/O and control-register access through narrowly scoped intrinsics or inline assembly with constraints.

### 3. Machine interface

- Constrained inline assembly or compiler intrinsics for `invlpg`, control registers, `rdmsr`/`wrmsr`, `cpuid`, `hlt`, `cli`/`sti`, and `in`/`out`.
- Function attributes for no-return, no-inline, naked/entry stubs and interrupt wrappers, with validation of legal combinations.
- Explicit section placement for `.text`, `.rodata`, `.data`, `.bss`, init and per-CPU sections.
- Linker-provided symbols represented without pretending they are ordinary allocated objects.

### 4. Runtime primitives

- `memcpy`, `memmove`, `memset` and `memcmp` with overlap and alignment tests.
- A panic/abort contract that cannot recurse through formatting or allocation.
- A minimal allocator interface whose failure behavior is explicit; no global allocator is assumed.
- No unwinder, exceptions, implicit stack probes or compiler-generated helper calls unless the runtime explicitly supplies them.

## Delivery sequence

### OS-0 — Freeze the current host contract

- Add regression tests for current Linux x86-64 assembly, entry symbol, syscalls and System V stack behavior.
- Record exact assembly/link commands and inspect generated instructions.
- Preserve `--asm` behavior while the new target path is developed.

**Exit gate:** existing tests and generated host binaries remain unchanged in behavior.

### OS-1 — Target description and freestanding object

- Add a validated target descriptor for `x86_64-unknown-none-elf`.
- Separate Linux process startup/syscalls from architecture instruction selection.
- Add `emit --target x86_64-unknown-none-elf --format elf` (final CLI spelling may differ).
- Emit ELF64 relocatable objects with correct machine ID, sections, symbols, string tables and relocations.
- Accept a linker script path without attempting to interpret arbitrary linker-script syntax inside the compiler.

**Exit gate:** a tiny integer-only freestanding object links with a test linker script; `readelf` and `objdump` confirm its metadata and code.

### OS-2 — Boot contract and memory layout

- Define a versioned boot handoff structure: memory map, framebuffer (optional), ACPI RSDP, modules, command line and physical address width.
- Provide a minimal assembly entry shim that establishes a known stack, clears direction flag, validates CPU mode assumptions and calls the Kyn entry.
- Define `.bss` zeroing and `.data` copy responsibilities exactly once (bootloader or startup shim, never both).
- Link a kernel image at an explicit virtual/physical layout and validate load segments.

**Exit gate:** boot under QEMU with serial output and no libc. Keep bootloader protocol implementation outside the compiler.

### OS-3 — CPU and interrupt foundation

- GDT/TSS and per-CPU state.
- IDT with exception stubs and normalized stack frames.
- APIC timer and interrupt masking discipline.
- Explicit interrupt wrapper ABI and register-preservation tests.

**Exit gate:** deliberate divide/page faults are reported through a serial panic path; timer interrupts do not corrupt interrupted state.

### OS-4 — Memory manager

- Physical frame allocator consuming the boot memory map.
- Page-table construction and mapping helpers.
- Kernel heap allocator with explicit ownership and failure contracts.
- Guard pages and stack boundaries where supported.

**Exit gate:** allocate/free/reuse frames, map/unmap pages and test permission faults under QEMU.

### OS-5 — Drivers and user boundary

- PCI enumeration, serial and timer drivers, then block and input devices.
- A documented kernel/user ABI and syscall transition mechanism.
- Separate user-space target from kernel target; do not conflate Linux syscalls with Kyn OS syscalls.

**Exit gate:** boot to a minimal shell or test task and execute a user program through the defined ABI.

## Validation matrix

Every OS-target change must add the narrowest applicable validation:

| Layer | Required evidence |
| --- | --- |
| Target parsing | valid/invalid target unit tests |
| Data layout | size/alignment/offset tests against C reference structs |
| ABI | register, stack alignment, spill and preserved-register tests |
| Code generation | assembly golden tests plus assembler acceptance |
| ELF | header/section/symbol/relocation inspection |
| Link | custom linker-script integration test |
| Boot | QEMU smoke test with serial log and bounded timeout |
| Hardware effects | assembly/IR assertions proving volatile/atomic operations |
| Regression | Linux `--asm` and LLVM tests remain green |

Performance claims require a reproducible benchmark and baseline. Correctness and ABI stability take priority over instruction-count tuning during the initial bring-up.

## Explicit non-goals for the first kernel milestone

- Supporting every x86-64 OS ABI.
- Shipping a bootloader as part of the compiler.
- C++-style exceptions, RTTI, unwinding or a mandatory runtime.
- SIMD before the kernel owns FPU/SSE state management.
- Premature generic metaprogramming or broad standard-library expansion.

## Current implementation boundary

As of the current implementation status, Kyn has a Linux x86-64 System V assembly backend that emits `_start`, Linux `write`/`exit` syscalls and pointer operations for its implemented language subset. It does **not** yet emit freestanding ELF objects, accept linker scripts, define a kernel ABI, provide interrupt attributes, preserve volatile MMIO accesses or boot a kernel. Keep [status.md](status.md) authoritative and update it only after executable evidence exists.
